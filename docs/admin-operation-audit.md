# 관리자 작업 상태 재점검

2026-10-31 재점검 대상은 등록·수정·삭제·업로드·공연 이동·번역 수정/재시도·뉴스레터 게시/발송 등록이다.

## 발견한 누락과 수정

- 공통 폼과 공연·프로젝트 폼은 저장 중 버튼을 비활성화했지만 문구가 바뀌지 않았다. `저장 중…`을 표시하도록 수정했다.
- 일반 콘텐츠의 삭제와 일부 저장은 성공 알림 없이 목록만 바뀌었다. 관리자 API 쓰기 요청을 공통 상태 영역에 연결해 `처리 중… / 성공 / 실패 / 취소됨`을 표시한다.
- 공통 오류 저장소에 오류를 넣어도 화면에서 소비하지 않는 경로가 있었다. 쓰기 요청 실패는 기존 개별 폼 처리와 별도로 공통 상태 영역에도 남는다. 로컬 폼 검증 오류는 기존 폼/대화상자가 처리한다.
- 같은 작업을 재시도하면 이전 실패 알림을 교체한다. 다른 작업이 진행 중인 상태를 지우지 않고, 늦게 완료된 요청의 결과도 보존한다. 진행 중 요청은 닫을 수 없고 완료 결과는 최근 3개까지 표시한다.
- 사진 관리 모달이 공통 알림을 가리는 경로도 보완했다. 모달 내부에도 작업 상태를 표시하고 실제 화면의 hit test로 다른 레이어에 가리지 않는지 검증한다.
- 모바일 공연 폼과 공통 CRUD 폼의 2열 입력이 화면 밖으로 넘쳐 버튼 클릭을 방해했다. 좁은 화면에서 1열로 배치하고 입력의 최소 너비를 제한했다.

컴포넌트/API 모의 검증과 실제 서버 검증은 구분한다. 모든 종류의 관리자 GUI 전체를 실제 서버에서 수동 조작했다고 해석하지 않는다. 실행 결과와 반복 검증의 최종 상태는 [testing.md](testing.md)에 기록한다.

전체 묶음 3회 연속 통과 후 관리자 화면만 다시 점검했다. 320·390·768·1366px의 등록/수정/삭제 복구와 사진 모달 상태 표시 8건이 재시도 없이 통과했다. 각 실행의 trace·스크린샷·HTML 리포트는 `.local/test-artifacts/admin-final-review`에 보관한다.

뉴스레터의 `발송 등록 성공`과 번역의 `재시도 등록 성공`은 서버가 작업을 접수했다는 뜻이다. 최종 발송/번역 결과는 기존 작업 기록과 상태 패널에서 확인한다. 자동 갱신하는 메일 미리보기는 공통 알림 대신 자체 진행·실패 표시를 유지한다.
