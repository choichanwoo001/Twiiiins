# 뉴스레터 운영

구독자와 콘텐츠는 사이트 DB에서 관리하며 기존 메일 계정의 SMTP로 발송합니다. 관리자 → Newsletter에서 영어·독일어 작성, 테스트 발송, News 게시, 구독자 관리, 발송 결과 확인을 할 수 있습니다. Media → News는 기존 날짜·제목·설명·사진 등록 화면을 유지하며, 일반 News는 저장 즉시 게시되고 이메일을 보내지 않습니다.

뉴스레터 초안은 공개되지 않습니다. Newsletter에서 게시하면 동일한 글이 Media의 News에 표시됩니다. News 목록의 `Newsletter에서 수정` 버튼으로 원본 편집 화면을 엽니다. 사진·삭제·보관도 Newsletter에서 관리하며, 수정은 웹 게시글에 반영되지만 이미 등록한 이메일 발송본은 바뀌지 않습니다. 구독자 탭에서는 이메일·수신 언어·상태·신청일과 전체 신청자 및 활성 구독자 수를 확인하고 검색·필터·발송 제외를 할 수 있습니다. 전체 신청자 수는 현재 보관 중인 신청 기록 기준입니다.

## 최초 배포

1. DB와 uploads를 백업하고 백엔드를 정지합니다. MySQL 8에서 `scripts/migrate-newsletter.sql`을 실행합니다. 스크립트는 재실행 가능하며 기존 News는 공개 상태로 유지하고 설명은 안전한 영어 HTML로 이전합니다. 출처는 기존 일반 글에 `NEWS`, 이전 통합 편집기의 초안·독일어 본문·발송 기록이 있는 글에 `NEWSLETTER`를 최초 한 번 지정합니다. 기존 사진의 순서 정보가 없으면 URL 기준으로 초기 순서를 정합니다.
2. 새 백엔드·프런트를 배포합니다. `backend/.env.newsletter.example`의 값을 서버 환경변수에 설정합니다. CI 배포는 같은 이름의 GitHub Actions secrets를 사용하므로 서버 `.env`에만 입력한 값은 다음 배포에서 유지되지 않습니다.
3. `NEWSLETTER_TOKEN_KEY`는 암호학적으로 안전한 난수로 최소 32자를 생성하고 비밀로 보관합니다. 바꾸면 기존 인증·해지 링크가 무효가 되므로 임의로 변경하지 않습니다. SMTP 비밀번호와 키는 저장소에 넣지 않습니다.
4. SMTP 계정이 뉴스레터 발송을 허용하는지, 계정의 분당·하루 한도 및 이미 사용 중인 발송량을 확인합니다. 기본값은 분당 10건·UTC 하루 300건이며 환영·테스트·재시도까지 포함합니다. 기존 계정의 다른 발송량은 이 시스템에서 집계할 수 없으므로 그만큼 여유를 두어 한도를 낮춥니다.
5. 발신 도메인의 SPF·DKIM·DMARC를 설정하고 발신자·Reply-To·운영자 이름과 주소를 확정합니다. `NEWSLETTER_OPERATOR`는 메일 하단에 표시됩니다. 영어·독일어 개인정보 안내에 실제 메일 제공업체·호스팅·운영자 정보를 기입합니다.
6. `NEWSLETTER_ENABLED=true`로 설정한 테스트 환경에서 즉시 구독 등록·환영 메일·언어 변경·해지와 영어·독일어 테스트 메일의 실수신을 확인합니다. Gmail·Outlook 등의 받은편지함과 스팸함, 모바일 표시도 확인한 뒤 운영에서 활성화합니다.

SMTP 기본값은 587 STARTTLS입니다. 465 TLS 계정은 `SMTP_PORT=465`, `SMTP_SSL=true`, `SMTP_STARTTLS=false`를 사용합니다. 로컬 Mailpit은 1025번, 인증·TLS 비활성으로 사용하고 실제 구독자를 입력하지 않습니다. 활성화 필수 설정이 없으면 사이트와 News 작성은 동작하지만 구독·발송은 비활성화됩니다.

현재 배포 워크플로는 DB 백업과 이전을 실행한 뒤 백엔드를 재시작합니다. 기존 관리자 계정은 보존됩니다. 새 계정은 명시한 `DEFAULT_ADMIN_USERNAME`·`DEFAULT_ADMIN_PASSWORD`가 있을 때만 생성됩니다. 이전 개발용 기본 비밀번호를 사용 중이면 운영 활성화 전에 변경해야 합니다.

## 발송과 장애 처리

- 사진 추가는 제목이나 버튼 주소를 저장하기 전에 가능합니다. 업로드한 사진은 작성 중인 화면에 반영되며, 글의 사진 목록은 ‘저장’을 누를 때 반영됩니다. 업로드 중에는 저장·게시·발송을 막아 사진이 빠진 내용으로 처리되지 않게 합니다.
- 작성 화면의 버튼은 초안 저장·화면 확인, 테스트 메일, 게시·구독자 발송의 세 영역으로 구분됩니다. 테스트는 선택한 테스트 주소 한 곳, 구독자 발송은 수신에 동의한 활성 구독자에게 보냅니다.
- Contact에서 이메일·언어를 입력하고 수신에 동의하면 즉시 활성 구독자로 등록하며 환영 메일을 발송합니다. 동일한 언어로 재신청하면 중복 등록·환영 메일을 만들지 않습니다. 언어 변경은 즉시 반영하며 변경 안내 메일은 마지막 신청 후 10분 간격으로 제한합니다. 해지 후 재가입하면 새 구독 버전을 사용하여 과거 대기 뉴스레터를 보내지 않습니다. 기존 인증 대기 주소를 일괄 활성화하지 않으며 기존 확인 링크 또는 새로운 동의 신청으로 활성화할 수 있습니다.
- `scripts/start-local.ps1`로 실행한 로컬 환경에서는 모든 메일을 Mailpit이 받습니다. 관리자 화면의 ‘로컬 메일함 열기’ 또는 `http://localhost:8025`에서 환영 메일과 뉴스레터를 확인합니다. `NEWSLETTER_LOCAL_MAILBOX_URL`은 로컬 개발에만 지정하며 사이트 주소와 메일함 주소가 모두 localhost 또는 127.0.0.1일 때만 관리자에게 표시됩니다.

- 한 글의 전체 발송은 한 번입니다. 게시 이후 수정은 웹에만 반영되며 이미 생성한 발송 회차의 내용과 이미지 참조는 유지됩니다. 발송 이력이 있는 글은 삭제 대신 보관되며 웹 보기 주소는 유지됩니다.
- 대기열은 DB에 저장됩니다. 현재 Docker 구성처럼 **백엔드 인스턴스 하나**로 운영합니다. 여러 인스턴스나 겹치는 배포는 지원하지 않습니다. 시작 시 미완료 SMTP 작업은 확인 필요로 전환하므로 롤링 방식으로 두 인스턴스를 동시에 실행하지 않습니다.
- SMTP 접수는 수신 서버의 접수 여부이며 실제 받은편지함 도착을 보장하지 않습니다. 반송 수신함은 운영자가 확인하고 문제가 있는 주소를 발송 제외합니다. 반송 자동 수집·열람 추적은 없습니다.
- 명확한 일시 오류는 최초 시도 후 최대 3회 재시도합니다. SMTP 인증 오류는 전체 대기열을 일시 정지합니다. 환경설정을 고치고 관리자 화면에서 발송 재개를 누릅니다. 확인 필요 상태는 자동·수동 재전송 대상이 아닙니다. SMTP 기록을 확인하여 중복 가능성을 판단해야 합니다.
- 수신 언어는 발송 회차를 만들 때 확정합니다. 그 뒤 언어 변경은 다음 회차부터 적용됩니다. 해지·발송 제외는 전송 직전에 다시 확인합니다. 이미 SMTP로 전송 중인 메일은 취소할 수 없습니다. 재가입해도 예전 대기 메일은 보내지 않습니다.
- 큐 상태·오류 코드는 관리자 화면에서 확인합니다. 서버 로그에는 수신자 이메일·인증 링크·SMTP 비밀번호를 기록하지 않습니다. 백엔드 포트는 호스트 루프백에만 노출하고 nginx를 통해 접근합니다. IP 제한은 신뢰하는 프록시가 전달한 실제 주소를 사용합니다.

## 보관과 정리

이전 방식의 확인 링크는 24시간 유효합니다. 이전 미인증 신청은 7일, 해지·제외 구독 기록은 30일, 수신자별 최종 발송 기록은 90일 후 시간별 정리 작업으로 삭제합니다. 발송 회차별 합계는 유지하며, 회차가 참조하는 이미지는 파일 정리 시 삭제하면 안 됩니다. 활성 구독과 개인정보 처리 안내의 동의 버전은 구독이 유지되는 동안 보관합니다. 백업은 별도의 보관 정책에 따라 관리합니다.

관리자 인증은 만료 8시간의 무작위 Bearer 토큰이며 서버에는 해시만 저장합니다. 로그아웃은 서버에서 폐기하고, 만료 토큰은 정리 작업이 삭제합니다. 공개 News API는 초안을 반환하지 않습니다.
