# 뉴스레터 운영

구독자와 콘텐츠는 사이트 DB에서 관리하며 기존 메일 계정의 SMTP로 발송합니다. 관리자 → Newsletter에서 영어·독일어 작성, 테스트 발송, News 게시, 구독자 관리, 발송 결과 확인을 할 수 있습니다. Media → News는 기존 날짜·제목·설명·사진 등록 화면을 유지하며, 일반 News는 저장 즉시 게시되고 이메일을 보내지 않습니다.

뉴스레터 초안은 공개되지 않습니다. Newsletter에서 게시하면 동일한 글이 Media의 News에 표시됩니다. News 목록의 `Newsletter에서 수정` 버튼으로 원본 편집 화면을 엽니다. 사진·삭제·보관도 Newsletter에서 관리하며, 수정은 웹 게시글에 반영되지만 이미 등록한 이메일 발송본은 바뀌지 않습니다. 구독자 탭에서는 이메일·수신 언어·상태·신청일과 전체 신청자 및 활성 구독자 수를 확인하고 검색·필터·발송 제외를 할 수 있습니다. 전체 신청자 수는 현재 보관 중인 신청 기록 기준입니다.

## 최초 배포

1. DB와 uploads를 백업하고 백엔드를 정지합니다. MySQL 8에서 `scripts/migrate-newsletter.sql`을 실행합니다. 스크립트는 재실행 가능하며 기존 News는 공개 상태로 유지하고 설명은 안전한 영어 HTML로 이전합니다. 출처는 기존 일반 글에 `NEWS`, 이전 통합 편집기의 초안·독일어 본문·발송 기록이 있는 글에 `NEWSLETTER`를 최초 한 번 지정합니다. 기존 사진의 순서 정보가 없으면 URL 기준으로 초기 순서를 정합니다.
2. 새 백엔드·프런트를 배포합니다. `backend/.env.newsletter.example`의 값을 서버 환경변수에 설정합니다. CI 배포는 같은 이름의 GitHub Actions secrets를 사용하므로 서버 `.env`에만 입력한 값은 다음 배포에서 유지되지 않습니다.
3. `NEWSLETTER_TOKEN_KEY`는 암호학적으로 안전한 난수로 최소 32자를 생성하고 비밀로 보관합니다. 바꾸면 기존 인증·해지 링크가 무효가 되므로 임의로 변경하지 않습니다. SMTP 비밀번호와 키는 저장소에 넣지 않습니다.
4. SMTP 계정이 뉴스레터 발송을 허용하는지, 계정의 분당·하루 한도 및 이미 사용 중인 발송량을 확인합니다. 기본값은 분당 10건·UTC 하루 500건이며 환영·테스트·재시도까지 포함합니다. GitHub Actions secret `NEWSLETTER_DAILY_LIMIT`에 값이 있으면 배포 시 기본값보다 우선합니다. 기존 계정의 다른 발송량은 이 시스템에서 집계할 수 없으므로 그만큼 여유를 두어 한도를 낮춥니다.
5. 발신 도메인의 SPF·DKIM·DMARC를 설정하고 발신자·Reply-To·운영자 이름과 주소를 확정합니다. `NEWSLETTER_OPERATOR`는 메일 하단에 표시됩니다. 영어·독일어 개인정보 안내에 실제 메일 제공업체·호스팅·운영자 정보를 기입합니다.
6. `NEWSLETTER_ENABLED=true`로 설정한 테스트 환경에서 즉시 구독 등록·환영 메일·중복 방지·해지와 영어·독일어 테스트 메일의 실수신을 확인합니다. Gmail·Outlook 등의 받은편지함과 스팸함, 모바일 표시도 확인한 뒤 운영에서 활성화합니다.

SMTP 기본값은 587 STARTTLS입니다. 465 TLS 계정은 `SMTP_PORT=465`, `SMTP_SSL=true`, `SMTP_STARTTLS=false`를 사용합니다. 로컬 Mailpit은 1025번, 인증·TLS 비활성으로 사용하고 실제 구독자를 입력하지 않습니다. 활성화 필수 설정이 없으면 사이트와 News 작성은 동작하지만 구독·발송은 비활성화됩니다.

### 준비 전 화면 및 설정 진단

- Contact의 구독 폼은 준비 완료·로딩·비활성·연결 오류에서도 같은 구조로 표시합니다. 준비 전에는 제출만 막고, 연결 오류에서 재시도해도 이메일·수신 언어·동의 값은 유지합니다.
- 더미 모드는 미리보기 전용입니다. 폼이 보이거나 미리보기 성공 안내가 나와도 실제 구독 저장·외부 메일 발송을 의미하지 않습니다.
- 관리자 → 뉴스레터에서 발송 불가 알림을 펼치면 `configurationIssues`에 대응하는 누락 항목을 확인할 수 있습니다. 진단은 필수 설정 조건과 동일한 기준을 사용하며 비밀번호·토큰 값은 반환하지 않습니다. 현재 발송 한도는 발송 기록에서 확인할 수 있습니다.
- 공개 `/api/newsletter/status`는 `available`과 활성화된 경우 Turnstile 공개 사이트 키를 반환합니다. `true`는 가입에 필요한 설정이 입력되었다는 뜻이며 실제 SMTP 인증·수신 성공까지 확인한 결과는 아닙니다.
- 배포 마지막 단계의 `scripts/check-newsletter-readiness.py`는 사이트 배포와 뉴스레터 준비 상태를 따로 보고합니다. 비활성이면 경고와 배포 요약을 남기고, 활성화를 명시한 배포에서 준비되지 않았거나 상태를 확인할 수 없으면 해당 확인 단계가 실패합니다. 이 검사는 가입·테스트 메일·구독자 발송을 실행하지 않습니다.

### 운영 연결 검증

- SMTP 설정은 GitHub Actions secrets에 등록합니다. 로컬 입력 파일은 `.env.smtp.local`이며 Git에서 제외됩니다. 기존 `NEWSLETTER_TOKEN_KEY`는 유지하고, 최초 설정일 때만 새 난수를 등록합니다.
- Actions의 `Newsletter operational check`를 수동 실행할 수 있습니다. `preflight`는 현재 준비 상태·토큰 키 존재 여부·발송 대기 건수를 읽기만 하며, 대기 건이 있으면 활성화 전에 검토하도록 실패합니다.
- `diagnose`는 저장된 글의 완성된 언어와 게시 가능 여부만 조회합니다. `verify-single-language`는 영어만 작성한 임시 글과 독일어만 작성한 임시 글을 각각 저장·게시하고, 두 언어 화면과 메일 미리보기에서 내용이 유지되는지 확인한 후 삭제합니다. 실제 이메일은 발송하지 않습니다.
- `verify`는 `NEWSLETTER_TEST_RECIPIENTS`의 첫 주소에만 영어·독일어 테스트 메일을 보냅니다. Turnstile이 활성화되어 있으면 가입과 해지는 지정 테스트 주소를 사용해 브라우저에서 확인합니다. Turnstile이 꺼져 있고 해당 주소가 기존 구독자 목록에 없으면 스크립트가 가입·환영 메일·중복 방지·해지를 검증합니다. 테스트 구독은 해지 상태로 남깁니다.
- `verify`의 검증용 초안은 게시하지 않고 삭제합니다. 서버 관리자 권한으로 만든 15분 만료 임시 세션은 모든 검증 종료 시 삭제합니다. 구독자 전체 발송 API는 호출하지 않습니다.
- `SMTP accepted`는 메일 서버가 발송 요청을 접수했다는 의미입니다. 실제 받은편지함·스팸함 도착 여부는 지정 수신자가 별도로 확인해야 합니다.

현재 배포 워크플로는 DB 백업과 이전을 실행한 뒤 백엔드를 재시작합니다. 기존 관리자 계정은 보존됩니다. 새 계정은 명시한 `DEFAULT_ADMIN_USERNAME`·`DEFAULT_ADMIN_PASSWORD`가 있을 때만 생성됩니다. 이전 개발용 기본 비밀번호를 사용 중이면 운영 활성화 전에 변경해야 합니다.

## 발송과 장애 처리

- 사진 추가는 제목이나 버튼 주소를 저장하기 전에 가능합니다. 업로드한 사진은 작성 중인 화면에 반영되며, 글의 사진 목록은 ‘저장’을 누를 때 반영됩니다. 업로드 중에는 저장·게시·발송을 막아 사진이 빠진 내용으로 처리되지 않게 합니다.
- 작성 화면에서 News에만 게시, News에 게시하고 발송, 구독자에게만 발송을 선택할 수 있습니다. 테스트는 선택한 주소 한 곳에 보내며, 구독자 발송은 수신에 동의한 활성 구독자를 대상으로 합니다.
- 발송 확인창은 실제 발송과 같은 기준으로 대상의 전체 인원과 수신 언어별 인원을 표시합니다. 구독자 탭은 주소별 기록을 세므로 같은 Gmail 받은편지함의 여러 주소가 각각 표시될 수 있습니다. 확인 후 대상 수나 언어별 인원이 달라지면 확인창을 다시 열어야 합니다.
- English 또는 Deutsch 중 한 언어의 제목·본문만 완성해도 게시·발송할 수 있습니다. 구독자나 사이트의 선택 언어에 완성된 내용이 없으면 작성된 언어의 제목과 본문을 함께 사용합니다. 자동 번역하거나 빈 메일을 보내지 않습니다. 초안 저장에는 둘 중 하나의 제목만 있으면 됩니다.
- Contact에서 이메일·언어를 입력하고 수신에 동의하면 즉시 활성 구독자로 등록하며 환영 메일을 발송합니다. 이미 활성 상태인 주소는 다시 제출해도 수신 언어가 유지됩니다. 해지 후 재가입하면 새 구독 버전을 사용하여 과거 대기 뉴스레터를 보내지 않습니다. 기존 인증 대기 주소는 기존 확인 링크 또는 새로운 동의 신청으로 활성화할 수 있습니다.
- `scripts/start-local.ps1`로 실행한 로컬 환경에서는 모든 메일을 Mailpit이 받습니다. 관리자 화면의 ‘로컬 메일함 열기’ 또는 `http://localhost:8025`에서 환영 메일과 뉴스레터를 확인합니다. `NEWSLETTER_LOCAL_MAILBOX_URL`은 로컬 개발에만 지정하며 사이트 주소와 메일함 주소가 모두 localhost 또는 127.0.0.1일 때만 관리자에게 표시됩니다.

- 한 글의 전체 발송은 한 번입니다. 구독자에게만 발송한 글은 별도로 게시하기 전까지 공개되지 않으며, 그 발송본에는 웹 보기 링크가 없습니다. 게시 이후 수정은 웹에 반영되며 이미 생성한 발송 회차의 내용과 이미지 참조는 유지됩니다. 발송 이력이 있는 글은 삭제 대신 보관되며, 공개 발송 메일의 웹 보기 주소는 유지됩니다.
- 대기열은 DB에 저장됩니다. 현재 Docker 구성처럼 **백엔드 인스턴스 하나**로 운영합니다. 여러 인스턴스나 겹치는 배포는 지원하지 않습니다. 시작 시 미완료 SMTP 작업은 확인 필요로 전환하므로 롤링 방식으로 두 인스턴스를 동시에 실행하지 않습니다.
- SMTP 접수는 수신 서버의 접수 여부이며 실제 받은편지함 도착을 보장하지 않습니다. 반송 수신함은 운영자가 확인하고 문제가 있는 주소를 발송 제외합니다. 반송 자동 수집·열람 추적은 없습니다.
- 명확한 일시 오류는 최초 시도 후 최대 3회 재시도합니다. SMTP 인증 오류는 전체 대기열을 일시 정지합니다. 환경설정을 고치고 관리자 화면에서 발송 재개를 누릅니다. 확인 필요 상태는 자동·수동 재전송 대상이 아닙니다. SMTP 기록을 확인하여 중복 가능성을 판단해야 합니다.
- 수신 언어는 발송 회차를 만들 때 확정합니다. 그 뒤 언어 변경은 다음 회차부터 적용됩니다. 해지·발송 제외는 전송 직전에 다시 확인합니다. 이미 SMTP로 전송 중인 메일은 취소할 수 없습니다. 재가입해도 예전 대기 메일은 보내지 않습니다.
- 큐 상태·오류 코드는 관리자 화면에서 확인합니다. 서버 로그에는 수신자 이메일·인증 링크·SMTP 비밀번호를 기록하지 않습니다. 백엔드 포트는 호스트 루프백에만 노출하고 nginx를 통해 접근합니다. IP 제한은 신뢰하는 프록시가 전달한 실제 주소를 사용합니다.

## 가입 보호

- 개인 `@gmail.com`은 `@` 앞의 점을 제거한 값으로 중복을 확인합니다. 새 주소는 입력받은 점 표기를 저장합니다. 마이그레이션은 기존 구독과 해지 링크를 보존합니다. 이전부터 같은 받은편지함으로 등록된 주소는 구독자 목록에서 검토할 수 있으며 새 표기는 추가 등록되지 않습니다.
- 기존에 중복 등록된 Gmail 받은편지함에는 가장 최근에 동의한 활성 주소의 언어로 한 통을 보냅니다. 해지가 더 최근이거나 순서를 확인할 수 없으면 해당 받은편지함은 제외합니다. 같은 받은편지함의 유효한 해지 링크는 구독 전체와 발송 대기 중인 뉴스레터에 적용됩니다. 재가입하면 해당 받은편지함의 이전 해지 링크가 만료되며 가입 안내 메일에 새 링크를 보냅니다.
- Cloudflare에서 Managed Turnstile 위젯을 만들고 공개 사이트 주소의 호스트를 등록합니다. GitHub Actions secrets에 `NEWSLETTER_TURNSTILE_SITE_KEY`와 `NEWSLETTER_TURNSTILE_SECRET_KEY`를 모두 등록한 뒤 배포합니다. 두 값을 비워 두면 봇 검증이 비활성화되며, 한 값만 있으면 공개 가입을 사용할 수 없습니다.
- 관리자 뉴스레터의 구독자 탭에서 서버 시작 이후 가입 성공, 중복 또는 발송 제외, 요청 제한, 검증 실패와 검증 서비스 오류 건수를 볼 수 있습니다. 집계는 재시작 시 초기화됩니다.

## 발송 제외 취소

관리자 → 뉴스레터 → 구독자에서 개인 Gmail 주소를 발송 제외하면 같은 받은편지함의 모든 주소에 적용합니다. ‘발송 제외 취소’를 누르면 각 주소는 이전 상태로 돌아갑니다. 제외 중 구독 해지한 주소와 이전 상태가 기록되지 않은 기존 제외 주소는 구독 해지 상태가 되며, 다시 받으려면 Contact에서 새로 신청해야 합니다. 제외를 취소해도 기존 대기 메일은 발송 제외로 처리됩니다.

## 전체 발송 운영 기준

- 발송 당일 관리자 → 뉴스레터 → 발송 기록에서 새로고침해 일일 사용량·잔여량과 대기열을 확인합니다. 사용량은 시스템에 기록된 가입 안내·테스트·뉴스레터·재시도를 포함한 SMTP 시도 횟수입니다. 다른 곳에서 같은 SMTP 계정으로 보낸 메일은 이 집계에 포함되지 않습니다. 한도에 도달해 남은 메일은 한국 시간 오전 9시 이후 같은 회차에서 이어서 발송합니다.
- 회차 종료 후 SMTP 접수·실패·확인 필요 건수를 확인하고 다음 날 반송함을 다시 확인합니다. 수신 거부와 주소 없음이 확인된 주소는 제외합니다. 한 번의 메일함 용량 초과는 구독 상태를 유지합니다.
- 운영자는 이 절차를 적용한 날부터 미신청 신고를 집계합니다. 이후에는 직전 검토를 종료한 시점부터 새로 셉니다. 동일한 수신자의 반복 신고와 같은 개인 Gmail 받은편지함의 여러 점 표기는 한 건으로 셉니다.
- 서로 다른 수신자 5명이 본인이 신청하지 않았다고 신고하면 운영자가 다음 전체 발송을 보류합니다. 관련 가입을 검토하고 확인된 문제 주소의 발송 제외 처리를 마친 뒤 전체 발송을 재개합니다. 가입량 급증은 검토 신호로 사용합니다.

## 보관과 정리

이전 방식의 확인 링크는 24시간 유효합니다. 이전 미인증 신청은 7일, 해지·제외 구독 기록은 30일, 수신자별 최종 발송 기록은 90일 후 시간별 정리 작업으로 삭제합니다. 발송 회차별 합계는 유지하며, 회차가 참조하는 이미지는 파일 정리 시 삭제하면 안 됩니다. 활성 구독과 개인정보 처리 안내의 동의 버전은 구독이 유지되는 동안 보관합니다. 백업은 별도의 보관 정책에 따라 관리합니다.

관리자 인증은 만료 8시간의 무작위 Bearer 토큰이며 서버에는 해시만 저장합니다. 로그아웃은 서버에서 폐기하고, 만료 토큰은 정리 작업이 삭제합니다. 공개 News API는 초안을 반환하지 않습니다.
